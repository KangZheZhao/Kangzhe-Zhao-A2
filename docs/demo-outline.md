# Demonstration outline

The video limit is 15 minutes. Each student should focus on their own contribution. Use this sequence to decide what to show, then explain it in your own words. Do not describe reference code as something you personally authored.

| Time | Show | Explain |
| --- | --- | --- |
| 0:00-1:00 | Public cPanel URL, folders and genuine contribution | Your work and the team's division of tasks |
| 1:00-3:00 | Tables and exported SQL | Relationships, email identity, keys and 10 sample registrations |
| 3:00-5:00 | Routes and an API response | Bound parameters, filters, ordering and errors |
| 5:00-7:00 | Controller, `$http` request and HTML binding | Request, response, rendering and validation |
| 7:00-9:00 | Calendar, combined and empty searches | How filters work together and no-match feedback |
| 9:00-11:00 | Two-ticket booking, receipt and refreshed list | Server timestamp/price, duplicates and capacity |
| 11:00-13:00 | Staff list, create/edit and blocked deletion | Statuses, registrations, version checks and suspension |
| 13:00-14:00 | Weather and a meaningful test | Event date/coordinates, missing forecasts and transaction protection |
| 14:00-15:00 | Real GitHub progress and both public copies | Individual implementation, testing and understanding |

Before recording, check the public site. Use a fictional email not already booked for that event. Prepare an unregistered test event for successful deletion, and explain why a booked event stays in the database.

Practise these questions: Why a child table? Why validate quantity again on the server? What if two people book the last tickets? Why snapshot the price? How is a stale edit rejected? What happens if Open-Meteo fails?

Upload the finished personal video to SCU OneDrive and supply a link the marker can open. No video has been generated or uploaded here.
